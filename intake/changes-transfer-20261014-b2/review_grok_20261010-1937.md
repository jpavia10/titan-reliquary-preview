## GRK-M-01 · `no-preference` animations ignore Calm/Off (Medium)

**Where:** js/app-motion.js:97 copies only rules whose media text matches `prefers-reduced-motion\s*:\s*reduce`.
Rules gated the other way keep following the operating system:
- styles/hall.css:118–125 `@media (prefers-reduced-motion: no-preference) { #pane-hall.hall-ready .hg-tile { animation: hgRise 0.7s … } … }`
- styles/themes.css:154–161 `@media (prefers-reduced-motion: no-preference) { html[data-atmo] { transition-property: --bg, …; transition-duration: 0.6s; } }`

There is no global `html[data-motion="off"] *` kill rule in the CSS (I grepped every `data-motion` selector).

**Reproduce:** on a phone or desktop with no OS reduce-motion setting, set Scene Studio > Settings > Motion to Off. Open the Hall: the glance tiles still rise in sequence. Switch theme: the colours still cross-fade for 0.6 s.
The settings note says "Off: nothing moves." (app-motion.js:169).

**Smallest fix (app-motion.js copyRules, :97–101):** also match `no-preference` rules.
- For those, push a copy scoped `html[data-motion="full"] <selector>`, using the same `scope()` helper with "full".
- Then switch off the original: `r.media.mediaText = "not all"` (CSSOM allows this on same-origin sheets).
- The rules then follow the in-app setting in both directions.

## GRK-M-02 · Full doesn't win over the phone in CSS (Medium)

**Where:** the matchMedia shim (app-motion.js:47–52) only affects JS. Native `@media (prefers-reduced-motion: reduce)` rules in about 30 sheets (styles.css ×7, splash.css ×3, worlds.css, scene.css, atmo/*.css …) still match the OS setting.
The header promises "A choice made here wins over the phone's setting" (:10). The copies at :100 only add calm/off rules; they never cancel the native ones.

**Reproduce:** turn on iOS/Android "Reduce motion", then in the app choose Motion: Full.
`TitanMotion.level()` is "full" and the GPU effects animate. But everything CSS-driven that the sheets stop under reduce stays stopped: the splash.css animations, the theme wordmark animations (e.g. atmo/neon.css), and the styles.css transitions.

**Smallest fix (app-motion.js:97–103):** after copying a reduce rule's children, remove the reduce query from the original rule's media list.
Two lists are compound, `(prefers-reduced-motion: reduce), (hover: none)` at atmo/kaleido.css:349 and study.css:374, so don't blank the whole list:
`var ml = r.media; for (var q = ml.length - 1; q >= 0; q--) if (/prefers-reduced-motion\s*:\s*reduce/i.test(ml[q])) ml.deleteMedium(ml[q]); if (!ml.length) ml.mediaText = "not all";`

The copies under `html[data-motion="calm"|"off"]` already carry those rules. `level()` defaults to calm when the phone asks to reduce (:32), so default behaviour doesn't change.

## GRK-M-03 · A track starts while paused (Medium)

**Where:**
- wings/music-recorded.js:53 schedules the next track with `setTimeout(next, 3000 + Math.random()*5000)` when one ends.
- :60 schedules a retry at 800 ms.
- The pause handler (:74–76) pauses only the elements already in `live`. It doesn't clear `gapT` or set any flag.
- So `next()` (:40–56) runs during the pause: it creates a new `Audio`, adds it to `live` and calls `el.play()` (:55).
- Meanwhile scene-engine `pause()` suspends the AudioContext 500 ms later (wings/scene-engine.js:1327). The element keeps playing into a suspended graph, which is the "runs on silently" case the comment at :72 was written to stop.

**Reproduce:** play a scene with a `rec` mood, wait for a track to end, and press pause within ~3 s.
Nothing is heard, but the network panel shows the next file streaming. Press resume a minute later and the piece is a minute in. The element was never paused (`el.paused` is false), so the `play` branch at :77 skips it.

**Smallest fix:**
- Add `let paused = false;` next to `live`. Set it in the handler: `paused = d.type === "pause" ? true : d.type === "play" ? false : paused;`.
- At :55 call `el.play()` only `if (!paused)`.
- On resume, the existing loop at :77 starts it, because it is paused and not ended.

## GRK-M-04 · A network drop mid-session ends the music for good (Low)

**Where:**
- music-recorded.js:57–61. Once `played > 0`, failures retry at 800 ms up to 3 times, then `stop()`.
- The fallback (`o.fallback`, generated music) is used only when `played === 0` (:59).
- `fails` resets only on a successful `playing` (:50).

**Reproduce:** start a piano scene online, let one track finish, and turn on airplane mode before the next track loads. After about 2.4 s the scene is silent for the rest of the session (until the scene changes).
**Smallest fix (:60):** `if (fails < 4) gapT = setTimeout(next, 800); else { stop(); if (o.fallback) o.fallback(); }`, the same fallback as the never-played case.

## GRK-M-05 · Recorded music missed on early starts (Low)

**Where:**
- music-recorded.js:22 `has(mood)` calls `load()` but returns synchronously, so it is false until the manifest has arrived.
- The manifest is first fetched at `load` + 1.5 s (:80).
- wings/scene-engine.js:1279 asks `has()` once at scene build. If false, the scene builds generated music and never upgrades.

**Reproduce:** with a cold cache, open the app and start a classical scene within about 2 s. You hear generated music, though the recordings are available.
**Smallest fix:** call `load()` at script start instead of after `load` + 1.5 s (:80). It is one small JSON file. Alternatively, in scene-engine, if `has()` is false but a `rec` mood is set, `TitanRecMusic.load().then(...)` and start the recording on the live group with a crossfade.
