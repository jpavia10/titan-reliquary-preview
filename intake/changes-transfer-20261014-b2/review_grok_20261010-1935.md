## GRK-R-01 · settle() rewards the record, not what the settling event said (High, executed)

**Where:** homework.py:433–453.
- :443 accepts any event whose field equals the disputed field or is a parent of it (`d["field"].startswith(f + ".")`).
- :444–445 require only a non-party author with a reference/photo source.
- :446–448 pick the winner by comparing the current record to the two sides.
- :450 then writes `error_by` = the loser.

**Trigger (executed):** I opened a synthetic disagreement D0999 on `type X issues.2.mintage`: the record is model:muse's value and the claim is model:grok-bot's.
model:gemini then writes `issues.2` (the whole issue object) with a Numista URL, only to fix `mint_text`, leaving the mintage as it was.
- Result: D0999 was resolved, winner "record", `error_by: model:grok-bot`.
- Gemini never looked at the mintage. Grok gets an error on its record, and the error counts feed `demoted()` (:511).
- The same thing happens if the owner touches any parent field for another reason (`owner` short-circuits at :444).

**Why it matters:** a wrong fact can stay in the record and be scored as confirmed, and the AI that challenged it can be demoted for being right.

**Smallest fix (homework.py:446):**
- Read the settling event's own value at the disputed path: `val = get_path({f: e.get("new")}, d["field"]) if f != d["field"] else e.get("new")`.
- Resolve only if `val` equals one side; otherwise `continue`.
- Set `win` from `val`, not from `cur`.

## GRK-R-02 · Anyone can close anyone's assignment (High, executed)

**Where:**
- homework.py:457–466 `answered()` collects every event whose `provenance.assignment` names an assignment id, whoever wrote it.
- apply_changes.py:391–396 (`assignment_of`) likewise accepts any author naming any assignment.
- The close/tried logic then marks the assignment's leftover items as tried by the *assignee*. Two tries park an item (homework.py:501, excluded at :515), and there is no unpark path.

**Trigger (executed):** I passed one event `by:"model:muse"`, `provenance.assignment:"HW-grok-value-20261010-1"` to `answered()`.
It returned `{'HW-grok-value-20261010-1': {('specimen','C129')}}`. Muse's line counts as Grok's answer.
A sloppy or hostile AI can close another AI's batch with one line per id. The assignee's real lines land later and count for nothing new. The untouched items get "tried by grok" and, after a second such event, are parked.

**Smallest fix (homework.py:461):** count an event only if `PV.agent_of(e.get("by")) == agent_of_assignment[pv["assignment"]]`.
Build that map once from `state["assignments"]`. Apply the same check in apply_changes `assignment_of`, and reject the line there with a clear message.

## GRK-R-03 · A verify can be an echo, and the gate can't tell (High)

**Where:**
- homework.py:601 `new = None if it["blind"] else cur`: every non-blind verify line arrives pre-filled with the current value.
- homework.py:623–624: the queue page shows the value *and* the first writer's source (`written by {author}: {their_source}`).
- The merge treats an unchanged `new` as a re-citation and Checked only needs two distinct agents with sourced supporters (provenance.py:253–255).

**Trigger:** the verifier keeps `new` as given and pastes the first writer's URL, or any URL, as its source. The fact becomes Checked.
Nothing compares the second source to the first, or proves the verifier read anything.
- The rules disagree on this. RESEARCH_LOOP.md §4 (≈ line 112) says re-reading the same entry is fine.
- The sheet's FILL text (homework.py:596) says "YOUR own exact source … (not the one shown)".
- A second AI that copies the shown URL is obeying the doc and breaking the sheet, and the gate accepts both.

**Smallest fix:**
- For numeric verify fields (mintage, weight, diameter, catalogs), make the sheet blind: `new = null`, and hide `value` and `their_source` on the page.
- Use a separate `numeric_blind` flag. Today `blind` also requires the vision capability (homework.py:473), so photo-blind can't be reused as-is.
- At merge, when a verify cites exactly the same URL as the supporter it would join, count it as a re-citation, not a second reader. One string compare in provenance.
- Make RESEARCH_LOOP.md §4 and the FILL text say the same thing.

## GRK-R-04 · Claude's re-filed lines count as Claude's own reading (Medium, live data)

**Where:** provenance.py:253–255 counts distinct `agent_of(by)` among sourced supporters. NOT_A_READER is only `{"ledger"}`.

**Evidence (live ledger at 026efe5):**
- 37 events carry notes such as "re-filed by Claude from Muse's …". They are written `by: model:claude…`.
- C003, C014, C067, C115 and C116 show catalog numbers as Checked "Claude + Grok", where Claude's source reads "Muse deep review MUS-2-05 + NGC …".
- The second reader there is Muse via Claude, not Claude.

**Why it matters:** Checked is supposed to mean two independent readings. A relay makes one AI's reading count twice, or count under the wrong name.

**Smallest fix:** when Claude re-files another AI's finding, write `provenance.refiled_from: "model:muse"` and have agent_of / the supporter count use it.
Alternatively, add "refiled" events to NOT_A_READER. For the existing 37, a one-off backfill of that field is enough.

## GRK-R-05 · "Reference" is any URL or the word "page" plus a number (Medium)

**Where:**
- provenance.py:31–32 REF_RE includes `https?://` and `\b(?:p\.|page|pp\.)\s*\d`.
- PHOTO_RE (:33) matches any mention of `.jpg/.png/.webp`.
- EXACT_REF is enforced only for REF_FIELDS (apply_changes.py:78–80: catalogs, composition, nominal, issues, mintage, legal tender, precious).

**Trigger:** two AIs each set or confirm `period`, `ruler`, `series`, `design` or `story` with sources like "https://www.google.com" or "my estimate, see page 2".
Both are classified "reference", and two distinct agents make it Checked.
A source like "no C001_obv.jpg available, guessed" is classified "photo".

**Smallest fix:**
- Require the URL in REF_RE to be a catalogue or price page (an allow-list of hosts: numista, ngccoin, pcgs, usmint, en.wikipedia, …). Drop the bare `page \d` alternative unless a book title is present.
- Anchor PHOTO_RE to the `photos/` path or a `C\d+_(obv|rev)` file name.

## GRK-R-06 · The rewriter becomes the "author" (Low)

**Where:** homework.py:222–230 `_story_state` takes the last story-changing event as the author.
**Trigger:** Muse writes a story with facts, and Grok does a plain-English rewrite. Grok is now the author, so a story-check can be handed to Muse, which then checks its own facts.
**Smallest fix:** take the author as the earliest event in the current chain whose kind is not plain-story (`provenance.kind != "plain-story"`). Exclude every author in that chain from story-check eligibility (homework.py:471).

## What held up

- An assignment is never handed out twice while open: `busy` and `taken` (homework.py:498–500) stop two open assignments writing the same field.
- Self-checking is blocked for direct authors: `eligible()` excludes `item["authors"]` (:471) and anyone who already tried (:474). The weak spots are relays (R-04), rewrites (R-06) and spoofed names (bridge GRK-B-03).
- Overwrites: I found no path in homework.py that writes collection data directly. It writes queue pages, sheets and its own state, so data still goes through apply_changes.
