## 01 — GRK-B-01: U+2028 / U+0085 line split in bridge intake (`d493481`)

**Files:**
- `tools/bridge/intake.py`, where `line_problems` changes.
- `tools/bridge/test_regress_grk_b01.py`, which is new.

**Problem:** `line_problems` checks lines with `str.splitlines()`, which also splits on U+2028/U+2029/U+0085/\x1c–\x1e. The merge reads the staged file with universal newlines, which split only on \n / \r\n / \r. So a line that carries `"by":"owner"` or `"verified"` after a U+2028 is checked as two harmless fragments. The merge then reads it as one owner/verified event, and the file is staged instead of held.

**Fix:** split on `\r\n`/`\r`/`\n` only, exactly as the reader does.

**Evidence:**
- Before: 3 of 4 tests FAIL. `classify` returns `'stage'`, where it should be `'held'`. The owner/verified line with `\u2028` is not held. `read_events` confirms the merge reads it as one owner event.
- After: 4/4 OK.

## 02 — GRK-B-02: `by:"owner\n"` passes the author regex (`9407d99`)

**Files:**
- `tools/pipeline/apply_changes.py`
- `tools/pipeline/test_regress_grk_b02.py`, which is new.

**Problem:** the `by` check used `re.match(r"^(owner|model:…)$")`. In Python, `$` also matches before a trailing `\n`, so `"owner\n"` and `"model:x\n"` passed the check.

**Fix:** use `re.fullmatch` for `by`, for the type id in `create_type`, and for the specimen id `[CT]\d{3,}`.

**Evidence:**
- Before: 2 of 3 tests FAIL (`'applied' != 'rejected'` for `owner\n` and `model:…\n`).
- After: 3/3 OK, and plain `owner` still applies.

## 03 — GRK-R-02: only the assignee can answer an assignment (`b77e10a`)

**Files:**
- `tools/agents/homework.py`
- `tools/pipeline/apply_changes.py`
- `tools/agents/test_regress_grk_r02.py`, which is new.

**Problem:** `answered()` and `assignment_of()` accepted any agent's line that cited an assignment id. A muse line could mark Grok's assignment as answered, or apply as if it were Grok's work.

**Fix:**
- `answered(ctx, owners=None)` skips events and disagreement claims whose `agent_of(by)` is not the assignee. `refresh` passes the `{id: agent}` map.
- `assignment_of` logs "assignment X belongs to <agent>, not …" and returns None when the author doesn't match.

**Evidence:**
- Before: the tests fail with a TypeError (old signature) and `'already-applied' != 'rejected'` (a muse stale line was treated as Grok's assignment).
- After: 3/3 OK.

## 04 — GRK-R-01: `settle` decides by the settling event's own value (`40e09b5`)

**Files:**
- `tools/agents/homework.py`
- `tools/agents/test_regress_grk_r01.py`, which is new.

**Problem:**
- Any later write to a parent path of a disputed field settled the disagreement.
- The winner was read from the current record, not from the event.

**Fix:**
- A third party settles only by writing the exact field. The owner may also settle via a parent field.
- The winner is taken from the event's own value: `e["new"]` for an exact write, or the sub-path inside the parent value.
- This differs from what my review proposed. Requiring "value equals one side" did not stop the parent re-statement case.

**Evidence:**
- Before: 2 of 4 tests FAIL. A parent write settled D0999, and the winner came back `'record'` instead of `'claim'`.
- After: 4/4 OK.

## 05 — GRK-S-01: `easeBack` NaN from `pow(negative, 3.)` (`2cd835f`)

**Files:** `wings/fx/styles-d.js` (one line).

**Problem:** GLSL `pow(x,y)` is undefined for x<0. `easeBack` passed it `x-1 ∈ [-1,0]`.

**Fix:** `float easeBack(float x){ x=clamp(x,0.,1.); float c=1.7, y=x-1.; return 1.+(c+1.)*y*y*y+c*y*y; }`

**Evidence:**
- CPU: the new formula equals the old one on [0,1] (max |Δ| = 6.7e-16).
- Headless Chrome / SwiftShader render, 256 sample points:
  - Before: **222/256 wrong** (NaN). This happened with native pow and also with emulated exp2/log2 lowering.
  - After: **0 wrong**.
- All 18 styles-d presets compile.
- Harness: `evidence/gl/` in the zip.

## 06 — GRK-M-03: pausing doesn't stop the next track from starting (`a0ee011`)

**Files:**
- `wings/music-recorded.js`
- `tools/music/test_regress_grk_m03.js`, which is new.

**Problem:** a pause during the gap between tracks didn't cancel the pending `next()`, so the next track began playing while the app was paused.

**Fix:**
- Add a `paused` flag, set by the `titan:gen` "pause" event and cleared by "play".
- `next()` loads the track but only calls `el.play()` when not paused.

**Evidence:** `node tools/music/test_regress_grk_m03.js` (vm with DOM/audio stubs).
- Before: FAIL "the next track does not start while paused".
- After: all passed, including "it starts on resume".

## 08 — GRK-M-01 + GRK-M-02: the Motion setting wins over the OS in CSS (`7bb6841`)

**Files:** `js/app-motion.js` (copyRules plus a small `unquery()` helper).

**Problems:**
- M-01: rules under `@media (prefers-reduced-motion: no-preference)` kept running with Motion Calm/Off on a phone with no OS preference. These are the hall.css Hall tile rise and the themes.css colour cross-fade.
- M-02: choosing Full on a phone set to reduce motion only changed the JS. Every native `@media (prefers-reduced-motion: reduce)` rule still applied.

**Fix:**
- `no-preference` rules are now also copied, scoped to `html[data-motion="full"]`.
- After copying, the OS reduce-motion query is removed from the original block's media list. Other queries in an OR list are kept. When none remain, the list becomes `not all`, because an empty list would match everything.
- Blocks holding anything but style rules (e.g. `@keyframes`) are left untouched.
- This assumes there are no `not (prefers-reduced-motion…)` queries. There are none in the repo.

**Evidence:** headless Chrome matrix, OS {none, reduce} × setting {none, full, calm, off}, using `--force-prefers-reduced-motion` for the reduce cases. Harness is in `evidence/motion/`.

| | before | after |
|---|---|---|
| OS none, setting Calm | no-preference animation still runs ✗ | stopped ✓ |
| OS none, setting Off | no-preference animation still runs ✗ | stopped ✓ |
| OS reduce, setting Full | transition 0s, animation none ✗ | transition 1s, animation runs ✓ |
| defaults: OS none / OS reduce | full / calm | full / calm (unchanged) |

- Before, 3 of the 8 cases were wrong. After, all 8 follow the setting.
- With the patch, the real app (`index.html`) loads with no errors. It builds 13 copied style sheets, including the 7 `data-motion="full"` Hall/theme rules.
