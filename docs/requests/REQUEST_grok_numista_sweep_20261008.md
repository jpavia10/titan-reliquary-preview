## How to answer
- One change file per batch, named `changes_grok-bot_{YYYYMMDD-HHMM}.jsonl`, dropped in Drive `Titan Reliquary/collection-incoming (AI change files)/`. Several batches in one file is fine too.
- One event per fact. `entity: "type"`, `id` = the worklist `type`, `field` = the path in the worklist `ask` (for example `nominal.weight_g`, `issues.3.mintage`, `catalogs`). `phase: 2`, `verified: false`.
- **Every `source` names the exact Numista URL** (`https://en.numista.com/catalogue/pieces{N}.html`) and, for a mintage, which row (year + mint mark). A brand name alone ("Numista") is rejected by the pipeline.
- `catalogs`: send the whole list (keep the existing entries, add `{"system": "Numista", "number": "N", "url": "..."}`); give `old` as the current list from the worklist.
- A coin whose mint mark we have not read: send the all-mints total and say so in `source`.
- If an entry does not give a fact, leave that fact out. Never estimate. If the entry disagrees with our record (wrong KM, wrong composition, wrong year range), send the correction with the URL and say what was wrong.
- `provenance` on every line (required from 2026-10-21): `model`, `prompt_version: "NUMISTA_SWEEP@2026-10-08"`, `workflow: "phase2-research"`, `inputs` (the Numista URLs you opened, as `{"file": URL}`), `run_id` (one per batch), `tokens`/`cost_usd` or null.
